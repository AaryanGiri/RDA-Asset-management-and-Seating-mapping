# Locus · Workplace OS — Flow Guide (for new users)

A one-page map of the two everyday flows: managing **where people sit** (Module A)
and tracking **the things the office owns** (Module B). An interactive version of
this guide is available as a shared page — ask an admin for the link.

## Roles

Switch roles any time from the **Admin / Employee** toggle in the top bar.

| Admin | Employee |
|---|---|
| Manages floor plans, seats & layout | Views their own seat & the floor map |
| Sets floor **Properties** (area & cost) | Requests a seat **change** or **swap** |
| Approves / rejects seat requests | Books meeting rooms |
| Assigns department colours | Tracks the status of their requests |
| Runs assets, movements & verification | No admin or approval controls |

## Module A — Seating & Workplace

From an employee's seat request to the map updating:

1. **See my seat** *(Employee)* — open **My Seat** to view your current seat, floor and zone.
2. **Request change / swap** *(Employee)* — ask for a vacant seat, or a swap with a colleague; add a reason + remarks and submit.
3. **Admin notified** *(System)* — the request lands in the **Seat Requests** inbox and an email-style alert is sent.
4. **Approve or reject** *(Admin)* — approve and the map updates automatically; reject with a reason.
5. **Seat updates** *(Employee)* — on approval the seat is reassigned (swaps exchange both) and the employee is notified.

**Admin also runs the floor directly:** allocate / move / block / maintenance any seat · edit the
layout (rooms, walls, seats) · set **Floor Properties** (carpet + super built-up area, rental,
maintenance, overhead & misc cost) · colour the map by **department** · and track **Meeting Rooms**
— availability, bookings, a utilization chart, and a "still using this room?" prompt that frees idle bookings.

Seat statuses: **Vacant · Occupied · On notice · Maintenance · Blocked**.

## Module B — Asset Lifecycle

Every physical asset is QR-tagged and tracked:

1. **Register & tag** *(Admin)* — add the asset to the **Register** with a generated QR code + printable label.
2. **Scan to open** *(Anyone)* — scan the QR to open the asset **passport**: identity, location, custodian, photos, timeline.
3. **Verify condition** *(AI + Admin)* — monthly check; AI suggests a condition & confidence, Admin accepts / remarks / flags.
4. **Move (governed)** *(Admin)* — request → AI condition suggestion → approve → in-transit → **receipt scan** updates location.
5. **Analyse** *(Admin)* — **Asset Analytics** rolls up value, category, condition and verification compliance.

Asset conditions: **New / Good · Fair · Damaged / Beyond repair**.
**AI moments are assistive, not automatic** — a person always makes the final call.
